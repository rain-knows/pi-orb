## 2. 如何在不合成任何按键的情况下验证真实注册

Windows 的 `RegisterHotKey` 是**每个桌面一个全局槽位**。因此用**第二个真实 Electron 进程**作为竞争探针：

- 主应用运行时，探针**无法**注册同一快捷键 → 证明该槽位确实被主应用持有（不是"某个布尔值被设为 true"）；
- 主应用退出后，探针**可以**注册 → 证明退出真的释放了注册。

这样验证的是 OS 级事实，而不是我们自己的返回值。**全程未向用户桌面发送任何合成按键**（`syntheticKeyEvents: 0`）。

## 3. 验收项实测（20/20）

### 3.1 注册与冲突诊断

| 断言 | 实测 |
|---|---|
| 配置的快捷键已注册到 OS | `shortcutRegistered=true` |
| 报告的快捷键等于配置值 | `Control+Alt+F9` |
| 注册成功时无问题信息 | `shortcutProblem=null` |
| **第二个进程无法注册同一快捷键** | `registered=false` |
| **冲突被诊断为可操作原因** | `Another application already owns this shortcut. Choose a different one.` |

最后一条是 P1-03"注册失败可诊断"的直接证据：Electron 的 `register()` 对"格式错误"和"被占用"都只返回 `false`，所以先做形状校验，否则用户会被告诉错误的问题。

### 3.2 无效输入的拒绝

| 输入 | 实测结果 |
|---|---|
| `NotAKey` | 拒绝，理由 `"NotAKey" is not a recognized key or modifier.` |
| `Alt+Alt`（纯修饰键） | 拒绝，理由 `A shortcut needs a key, not only modifiers.` |
| 空白 | 拒绝并给出提示 |
| 以上任一被拒后 | **原快捷键仍处于注册状态**，且**未被持久化**（配置值不变） |

"拒绝但保持可用"是刻意的设计：一个不能触发的快捷键会让悬浮窗无法唤醒，因此拒绝时不写入配置、并把上一个可用值重新注册回去。探针再次确认原槽位仍被持有。

### 3.3 改键与释放

| 断言 | 实测 |
|---|---|
| 新快捷键被接受并注册 | `Control+Alt+F10`，`registered=true` |
| **旧快捷键在改键时被释放** | 探针可注册 `Control+Alt+F9`（`registered=true`） |
| 新快捷键确实被占用 | 探针无法注册 `Control+Alt+F10` |
| **退出后槽位释放** | 探针可注册 `Control+Alt+F10`（`registered=true`） |

### 3.4 重复按不产生异常状态（单测）

全局快捷键在**长按时会自动重复**，同一逻辑也可能同时被快捷键与托盘触发。`WakeController` 用 250ms 冷却抑制：

**人工复测曾推翻「长按全程只触发一次」的推论。**仅用 250ms 冷却只能抑制短时间突发回调，
不能区分长按与下一次按下。当前实现增加 `uiohook-napi` 的 key-up edge guard：Electron
继续负责 OS 注册，hook 只负责在主键释放后解除一次性闩锁；hook 不可用时快捷键会失败并显示原因，
不会静默退回旧的重复触发行为。`tests/shortcut-edge-guard.test.ts` 覆盖长按重复、无关键释放、
改键和标点/F 键映射。`node evidence/p1-03/run-edge-guard-integration.mjs` 又在真实 Electron
进程中验证了两次 700ms 长按：OS 回调 2 次、实际接受 2 次；该探针使用合成 F24 输入，不能替代真实键盘长按。

| 单测用例 | 覆盖 |
|---|---|
| 长按（20 次、间隔 10ms） | 只应用 1 次，窗口状态不翻转 |
| 快捷键 + 托盘同时触发 | 第二次被抑制，不发生双重应用 |
| 冷却期后 | 仍能正常收起/唤醒，唤醒不会被永久屏蔽 |
| 可见但未聚焦 | 执行**唤醒**而非隐藏（用户伸手唤醒时想要的不是把它藏起来） |
| 最小化窗口 | 执行唤醒（并 `restore()`），不会因"可见"而被误判为收起 |
| 已销毁窗口 | 不操作 |

冷却机制同时满足 P1-03 的"重复按不新建重复会话"：唤醒路径**只改可见性**，不创建会话、不发消息（`wake` 的唯一协作者就是窗口目标，单测断言无其它副作用）。

### 3.5 唤醒不自动截图或上传

当前代码中**不存在**任何截图或上传路径：`WakeController` 的 `wake()` 只调用 Electron 的 `restore()`/`show()`/`focus()`。截图能力属 P1-04，届时必须显式保持"唤醒本身不上传"这一约束。

## 4. 本阶段发现并修复的真实问题

### 校验通过的形式与注册的形式不一致

校验时容忍了 `Control++Alt+O` 这类重复分隔符（拆出空段后过滤），但传给 Electron 的**是原始字符串**。后果是：这里判为合法、OS 判为非法，而 `register()` 的 `false` 会被解释成"被其它程序占用"——把格式错误报成冲突。

修复：拒绝空段并给出针对性理由，同时让校验返回**规范化后的字符串**（`normalized`），注册使用该值、持久化也使用该值，使"校验的是什么"与"注册的是什么"严格一致。

### 快捷键失败原因此前不进入用户可见状态

仅 `console.warn` 到主进程日志，用户看不到。现纳入状态快照（`shortcutProblem`）并在界面显示。

### 人工验证步骤

```powershell
npm run build
npm run start
```

1. 焦点切到其它程序，按下快捷键（默认 `Ctrl+Shift+Space`）→ 悬浮窗应出现并获得焦点。
2. 保持悬浮窗为前台，再次按下 → 悬浮窗应收起。
3. 让其它窗口遮住悬浮窗（悬浮窗可见但不聚焦），按下 → 应重新回到前台，而**不是**被隐藏。
4. 长按快捷键不放 → 悬浮窗应在一次唤醒/收起后保持稳定，不得反复翻转。
5. 单击托盘图标两次（间隔超过 250ms）→ 第一次显示，第二次收起。托盘是显式 toggle；冷却只抑制紧邻的重复回调。
6. 在界面展开 "Wake shortcut"，填入一个**已被其它软件占用**的组合（如 `Ctrl+Alt+Del` 类常用键）→ 应显示"已被其它程序占用"而不是静默失败，且原快捷键仍可用。
7. 退出应用后，在同一台机器上启动任意其它注册该快捷键的程序 → 应能注册成功（槽位已释放）。

记录结果时需包含：OS 版本、键盘布局、Electron 版本，以及每一项的实际表现。
