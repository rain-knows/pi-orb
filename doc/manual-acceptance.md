# pi-Orb 人工验收清单（P1）

本文件是**唯一**的人工验收入口。它只包含自动化无法诚实覆盖的项：真实按键、真实桌面观感、需要
第二显示器或高权限窗口的场景、以及需要真实模型在环的项。

自动化已经证明的项**不在此列**，且不得因为出现在本文件里就被当成「未验证」——每一项的当前状态
见 `doc/support-matrix.md`；那里是结论的唯一来源。

## 0. 为什么这些项必须人工

| 类别 | 自动化为什么做不到 |
|---|---|
| 真实按键唤醒/收起 | 合成按键只能证明「注册到了 OS」与「冲突可诊断」，不能证明人手按下时的真实行为与体验 |
| 第二显示器、高权限窗口 | 本机只有 1 个显示器；按目标要求不自动提权 |
| 「按下中途取消」 | 需要在真实前台下按住再撤销，与驱动级 session 结束不是同一件事 |
| 真实模型自主调用工具 | 需要真实模型在环；自动化只能证明「provider 收到了 schema」与「策略会执行」 |

## 1. 前置条件

| 项 | 要求 | 自检命令 |
|---|---|---|
| 平台 | Windows 11 x64（首发仅此平台） | `[Environment]::OSVersion.VersionString` |
| Node | `24.19.0`（见 `doc/tech-stack.md`） | `node -v` |
| 构建产物 | 已构建（原生 helper 必须被拷进产物） | `npm run build`；确认 `out/main/native/foreground-window.ps1` 存在 |
| pi-web | 已在 `http://127.0.0.1:30141` 运行 | `Invoke-WebRequest http://127.0.0.1:30141/api/web-auth` |
| 模型 | pi-web 侧已配置一个支持工具调用、且最好支持图像的模型 | 在 pi-web 界面确认 |
| Orb 工作区 | 在浮窗里点 **Choose workspace…** 选定一个专用目录 | 未选工作区时 Orb 模式**不会**启用（这是设计，不是故障） |

环境变量（可选，见 `README.md`）：`PI_ORB_PI_WEB_URL`、`PI_ORB_PI_WEB_PASSWORD`、
`PI_ORB_CONFIG`。

### 安全底线（全部步骤适用）

- 只对**本次为验收新建的丢弃式窗口**操作，不要用真实浏览器标签、真实文档、真实凭据。
- 不自动提权；需要高权限窗口时必须**由你手动**创建并明确授权测试。
- 输入只发往丢弃式目标；不要用真实桌面作为落点。
- 发现异常立即按 `Ctrl+Shift+Space` 收起浮窗（收起即撤权）。

## 2. 记录规则

每条结果只能填这五种之一，不得含糊：

| 结论 | 判据 |
|---|---|
| `通过` | **目标自身**的事件日志／读回内容／系统状态证明成功。不接受「驱动说成功了」 |
| `失败` | 产品行为确实违反预期（需附日志或截图路径） |
| `未验证` | 环境不具备条件（如没有第二显示器）——**不算未通过，也不算通过** |
| `驱动报成功但目标未收到` | 归入 `失败` 或 `未验证`，**不能算通过** |
| `不适用` | 该项在本机不可能构造，注明原因 |

记录需包含：OS 版本、键盘布局、Electron 版本、实际表现、证据文件路径。

## 3. A 组：快捷键真实体验（P1-03）

```powershell
npm run build
npm run start
```

默认快捷键 `Ctrl+Shift+Space`（可在浮窗内 **Wake shortcut** 处修改并按 **Apply**）。

| # | 操作 | 预期 | 结果 |
|---|---|---|---|
| A1 | 焦点切到其它程序，按一次快捷键 | 浮窗出现**并获得焦点** | |
| A2 | 保持浮窗为前台，再按一次 | 浮窗收起 | |
| A3 | 让其它窗口遮住浮窗（可见但不聚焦），按一次 | 回到前台，**不是**被隐藏 | |
| A4 | 长按快捷键不放 | 只切换一次，不得反复翻转 | |
| A5 | 单击任务栏托盘图标 | 行为与快捷键一致（同样受冷却抑制） | |
| A6 | 托盘右键菜单：Show orb / Hide orb | 分别显式显示、显式收起；Hide 与快捷键收起效果一致 | |
| A7 | 在 Wake shortcut 填入一个已被占用的组合（如 `Ctrl+Alt+P` 被其它软件占用） | 显示「已被其它程序占用」，**不是**静默失败；原快捷键仍可用 | |
| A8 | 让其它窗口遮住浮窗，然后点浮窗右上角关闭按钮 | 收起并**撤权**（不得留下仍可执行桌面操作的授权） | |
| A9 | 退出 pi-Orb，在同机启动另一个注册同一快捷键的程序 | 能注册成功（槽位已释放） | |
| A10 | 切换到非 US 键盘布局（如德语）后重复 A1–A2 | 行为不变；记录布局名 | |
| A11 | 锁屏后解锁（或休眠唤醒）后重复 A1–A2 | 快捷键仍可用、无卡键 | |

**证据落点**：结果写入 `evidence/p1-03/README.md` §5 的表，并保留一份实际表现记录。

## 4. B 组：截图授权与正向路径（P1-04）

正向路径（记录目标 → 按句柄捕获 → 预览 → 确认发送）已由 `evidence/p1-04/run-p1-04.mjs`
自动化验证（41/41）。人工只需补自动化无法构造的场景。

先用记事本或任意普通程序打开一个**非敏感**文件作为目标。

| # | 操作 | 预期 | 结果 |
|---|---|---|---|
| B1 | 让目标窗口在前台，按唤醒快捷键，然后点 **Screenshot** | 出现预览；预览的是**你刚才那个目标窗口**，不是浮窗自己 | |
| B2 | 检查预览图 | 不含 Orb 浮窗自身的遮挡（无遮罩、无浮窗边缘） | |
| B3 | 点 **Discard** | 不上传任何内容；会话里不得出现图片 | |
| B4 | 重新截图后点 **Send with message**（或 **Send**） | 图片进入**当前 Orb 会话**，不是别的会话 | |
| B5 | 记录目标后**关闭该目标窗口**，再点 Screenshot | 拒绝并说明原因；**不得**改截整屏、不得上传 | |
| B6 | 记录目标后把目标挪到另一个位置再截图 | 截到的仍是同一窗口（按句柄），且预览与之相符 | |
| B7 | （若有多显示器）在第二显示器上重复 B1，记录两屏的 DPI | 两个显示器的坐标与尺寸都正确 | |
| B8 | （需你手动创建并授权）对一个**高权限**窗口重复 B1 | 行为可预期；记录是否拒绝 | |
| B9 | 用仅支持文本的模型发起截图任务 | 明确拒绝或说明不支持图像，**不得**静默发送图像 | |

**证据落点**：`evidence/p1-04/README.md` §4.4 的表。

## 5. C 组：真机输入（P1-05）

自动化已定论的部分（无需人工重复）：后台点击 4/4 命中格心、**前台点击**产生真实 `mouse-down`、
**前台滚动**产生真实 `wheel` 且滚动条实际位移、后台输入经读回证实、无按键/鼠标残留。

```powershell
npm run build
node evidence/p1-05/run-p1-05.mjs
```

脚本会用**丢弃式** Electron 网格目标与临时文件记事本自证。人工只需要观察机器级现象：

| # | 观察 | 预期 | 结果 |
|---|---|---|---|
| C1 | 重跑上面的命令，看输出里 `stripActuallyScrolled` | 记为 `true` 时为本次实测定论（判定读的是目标自身事件日志） | |
| C2 | 前台投递发生时**鼠标指针** | 记录是否发生可见位移（`SendInput` 会移动真实指针）；这是体验代价，不是缺陷 | |
| C3 | 前台投递结束后，原来的前台窗口 | 应被**恢复**；记录实际表现 | |
| C4 | 脚本结束后检查键盘 | 无卡键（脚本已用 OS 全局键态差分自检，可另按一次修饰键确认） | |
| C5 | 对一个**高权限**丢弃窗口重复输入测试 | 记录普通 vs 高权限的差异 | |
| C6 | 在真实前台下构造「按下中途取消」 | 松开后无残留按下状态 | |
| C7 | **截图点 ↔ 输入点一致性（联合断言）**：先截图，在预览里选一个明确的标记点（如网格某格中心），再让 Orb 在该点点击 | 目标报告**同一格**被命中 | |

C7 是当前唯一把「截图坐标」与「输入坐标」放在同一次运行里对照的检查，因此不得由
B1/B7 与 C1 的分段结果代替。

**证据落点**：`evidence/p1-05/README.md` §6 的表。

## 6. D 组：真实模型自主调用工具（P1-06）

自动化已证明：普通会话拿不到 orb 工具、Orb 会话恰好四个、工具 schema 由 provider 实收（7/7）、
授权/预算/新鲜度/拒绝零副作用、真实点击闭环（38/38）。**未证明的是「模型决定去调用」这个连接点。**

1. 在浮窗里选好 Orb 工作区（精确匹配该目录，见 §1）。
2. 为验收新建一个**丢弃式**目标窗口，放在前台。可用的已入仓目标：
   - `evidence/p1-05/target-app`（Electron 网格窗口，自报收到的点击/按键/滚轮，最适合坐标类验证）
   - 记事本 + 一个临时文件（原生文本框，最适合文本输入验证）

   P1-06 的自动化脚本也是复用 `evidence/p1-05/target-app`。
3. 在浮窗里按 **Screenshot** 并发送，然后提出一个**明确、低风险、单步**的要求，例如
   「看一下当前窗口，然后点一下最左上角的格子」。
4. 观察：

| # | 观察 | 预期 | 结果 |
|---|---|---|---|
| D1 | 模型是否**实际发起** `orb_observe` 调用 | 是；你应看到一次观察结果回来 | |
| D2 | 随后是否发起 `orb_click`，且**坐标**来自刚才的观察 | 是 | |
| D3 | 每次动作之后是否产生**新的观察** | 是（一动作一观察） | |
| D4 | 目标窗口是否报告命中了预期位置 | 是 | |
| D5 | 浮窗里的桌面任务面板是否显示状态，且能 **Revoke** | 能撤销；撤销后不再执行 | |
| D6 | 让模型尝试滚动（`orb_scroll`） | 目标收到 `wheel`；若被 OS 拒绝，产品须如实报失败，**不得**报成功 | |
| D7 | 在**普通（非 Orb）**会话里要求模型操作桌面 | 无 orb 工具可用，模型无法调用 | |
| D8 | 让模型输入一段非敏感文本（`orb_type`） | 落到丢弃式目标的文本区；记录 Chromium 内容上是否可用 | |

> D8 的已知边界：驱动对 Chromium/Electron **内容**的文本投递不可用（后台被拒、前台需真实前台窗口）。
> 用在原生文本框（如记事本）上更容易得到定论。

**证据落点**：`evidence/p1-06/README.md` §6 的表。
