# pi-orb 人工验收清单（P1）

本文件是**唯一**的人工验收入口。它只包含自动化无法诚实覆盖的项：真实按键、真实桌面观感、需要
第二显示器或高权限窗口的场景、以及需要真实模型在环的项。

自动化已经证明的项**不在此列**，且不得因为出现在本文件里就被当成「未验证」——每一项的当前状态
见 `doc/support-matrix.md`；那里是结论的唯一来源。

## 0. 为什么这些项必须人工

| 类别 | 自动化为什么做不到 |
|---|---|
| 真实按键唤醒/收起 | 合成按键只能证明「注册到了 OS」与「冲突可诊断」，不能证明人手按下时的真实行为与体验 |
| 第二显示器、高权限窗口 | 本机只有 1 个显示器；按目标要求不自动提权 |
| 「按下中途取消」 | 需要在真实前台下按住再撤销，与驱动级 session 结束不是同一件事 |
| 真实模型自主调用工具 | 需要真实模型在环；自动化只能证明「provider 收到了 schema」与「策略会执行」 |

### 1.1 D 组必需：把 orb 扩展装进 Pi 配置

**这是一个真实的安装步骤，不是可选项。** 产品**不会**自动把扩展写进你的 Pi 配置（那样做会静默修改你的环境）。
未装载时，任何会话（包括浮窗自己的会话）都不会有 `orb_*` 工具，D 组无法开始。

运行 pi-web 的 Pi 从 `~/.pi/agent/settings.json` 读取声明（本机为
`C:\Users\JUSTLIKEZYP\.pi\agent\settings.json`）。用官方 CLI 声明本地包：

```powershell
pi install D:\workself\pi-orb\pi-package

# 确认已写入
pi list
```

- 实测：无论传绝对路径还是 `./pi-package`，CLI 都会把它归一成**相对 settings 文件**的路径
  （存储为 `..\..\workself\pi-orb\pi-package`）并在 `pi list` 中正确解析回 `D:\workself\pi-orb\pi-package`。
  两种写法都可以，不存在“相对当前目录”的坑。注意 CLI 写入的是 **`packages` 数组**，
  不是 `extensions` 键——不要到 `extensions` 里找它。

- 写入的是**你的**全局 Pi 配置。反悔时：`pi remove D:\workself\pi-orb\pi-package`。
- 本地包是「按解析后的路径加载、不复制文件」，因此 `orb.ts` 里指向仓库
  `src/shared/` 的相对 `import` 仍能解析（这正是测试用的加载方式）。
- 装完必须**重启 pi-web**（Pi 在进程启动时读配置）。
- 推荐顺序：`pi install` → 启动浮窗并选好工作区（这一步才会写出
  `%APPDATA%\pi-orb\orb-config.json`，没有它 Orb 模式不会激活）→ 重启 pi-web → 开始 D 组。
- 想先确认扩展能被加载，可单独跑 `node evidence/p1-06/run-p1-06-tools.mjs`：
  它在隔离目录里验证「provider 实际收到的工具 schema」，**不碰你的配置**。

若不想改动全局配置，D 组直接记为 `未验证` 并在 `evidence/p1-06/README.md` 写明原因。
**不得**因此把它当作已通过。

环境变量（可选，见 [`README.md`](../README.md)）：`PI_ORB_PI_WEB_URL`、`PI_ORB_PI_WEB_PASSWORD`、`PI_ORB_CONFIG`。

### 安全底线（全部步骤适用）

- 只对**本次为验收新建的丢弃式窗口**操作，不要用真实浏览器标签、真实文档、真实凭据。
- 不自动提权；需要高权限窗口时必须**由你手动**创建并明确授权测试。
- 输入只发往丢弃式目标；不要用真实桌面作为落点。
- 发现异常立即按 `Ctrl+Shift+Space` 收起浮窗（收起即撤权）。

## 2. 记录规则

每条结果只能填这五种之一，不得含糊：

| 结论 | 判据 |
|---|---|
| `通过` | **目标自身**的事件日志／读回内容／系统状态证明成功。不接受「驱动说成功了」 |
| `失败` | 产品行为确实违反预期（需附日志或截图路径） |
| `未验证` | 环境不具备条件（如没有第二显示器）——**不算未通过，也不算通过** |
| `驱动报成功但目标未收到` | 归入 `失败` 或 `未验证`，**不能算通过** |
| `不适用` | 该项在本机不可能构造，注明原因 |

记录需包含：OS 版本、键盘布局、Electron 版本、实际表现、证据文件路径。

### C7 的实测方法

**推荐：直接跑已入仓的真实模型 harness**，它把下面全部步骤自动化且不碰你正在运行的浮窗：

```powershell
npm run build
node evidence/p1-06/run-real-model-c7.mjs
```

它使用**真实 pi-web + 真实模型**（隔离 workspace、隔离 `--user-data-dir`、真实 agent 配置以硬链接/符号链接接入，**不复制凭据**）。
前置：**必须先解锁工作站**——锁屏下任何窗口都无法被前置，harness 会在发送任何消息前停下并说明原因。
结果读 `evidence/p1-06/real-model-c7-reference-backend.json`。

**手工做法**（与 harness 等价，但需要你自己看界面）：在一个新的 PowerShell 窗口启动丢弃式网格目标，日志落在临时目录：

```powershell
$env:P1_05_TARGET_LOG = Join-Path $env:TEMP 'pi-orb-c7-grid.jsonl'
$env:P1_05_TARGET_GEOMETRY = Join-Path $env:TEMP 'pi-orb-c7-geometry.json'
& .\node_modules\electron\dist\electron.exe .\evidence\p1-05\target-app
```

让网格窗口位于前台，用快捷键唤醒 Orb。先在桌面任务面板确认 **Target window** 是
`P1-05 input target`（否则点 **Choose target window…** 选它），将授权范围填为
「点击这张截图中左上角 `0,0` 单元格中心一次」并点 **Approve desktop task**。
在消息框输入「看刚才的目标窗口截图。先调用 `orb_observe`，再根据截图中左上角标记 `0,0`
的格子位置调用一次 `orb_click`。x/y 使用截图相对的 0–1000 坐标，不要用屏幕绝对坐标，
也不要点别处」，然后点 **Screenshot**。在预览里确认左上角单元格确实标记为 `0,0`，
再点 **Send with message**。完成后读目标自身日志：

```powershell
Get-Content (Join-Path $env:TEMP 'pi-orb-c7-grid.jsonl') -Tail 30
```

只有本次截图确实显示 `0,0`、工具调用发生在这张截图之后、日志出现 `cell-mousedown` 且
`cell` 为 `0,0`，才把 C7 记为 `通过`；记录截图预览、工具调用和 JSONL 日志的证据路径。
坐标必须用**截图相对的 0–1000 分数**（模型从图里读得到）；不得用屏幕绝对坐标——
模型拿不到窗口在屏幕上的位置，这正是修复前会点错格的根因。

**证据落点**：`evidence/p1-05/README.md` §6 的表。

## 10. F 组：`orb_open_app` 的真实桌面效果（P2-04）

`orb_open_app` 已于本轮按用户决定开放，但语义被收窄为**只激活已在运行的应用，不启动进程**。
自动化已证明的部分：`name` 参数拒绝路径／参数片段／shell 元字符；应用未在运行时动作失败且
不调用 `launch`；激活后前台窗口不属于该应用时不重绑定、保留原目标；工具 schema 由 provider
实收（`evidence/p1-06/tool-exposure.json`）。

自动化**无法**证明的是它在真实桌面上的效果与观感——需要两个真正在运行的应用和一个已授权的
任务。前置：Orb 已选好工作区；打开两个**丢弃式**应用窗口（例如一个记事本、一个计算器或另一个
记事本窗口），不要用真实文档、真实浏览器标签或任何含凭据的窗口；在面板里选定其中一个为目标、
填写任务范围并 Approve。

| 编号 | 步骤 | 预期 | 结论 |
|---|---|---|---|
| F1 | 让模型调用 `orb_open_app`，`name` 用**正在运行的另一个应用**的显示名 | 该应用被前置；返回的新观察窗口属于该应用 | |
| F2 | 观察浮窗的桌面任务面板 | 目标标题变成新应用的窗口（说明重绑定对用户可见），动作计数 +1 | |
| F3 | 继续一个动作（例如 `orb_click`） | 动作落在**新**目标窗口上，而不是原来的窗口 | |
| F4 | 让模型对**未运行**的应用调用 `orb_open_app` | 动作失败并说明「未运行、不会启动」；目标不变；桌面上**没有**新进程出现（任务管理器确认） | |
| F5 | 在 F1 之后点 **Revoke**，再观察 | 重绑定被清除；后续动作不再以新应用为目标 | |
| F6 | 再让模型尝试 `name` 里带参数（如 `notepad /A file.txt`） | 在授权校验层被拒（`invalid-app-name`），不产生任何桌面副作用 | |

结论含义：F1–F3 决定「重绑定是否真的按规则工作」，F4/F5/F6 决定「收窄是否真的收窄」。
任一项得到结论后回写本表并同步 `doc/support-matrix.md`（`orb_open_app` 的真实桌面效果一项）。
